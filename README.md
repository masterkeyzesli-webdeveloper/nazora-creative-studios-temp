# Nazora Creative Studios — Website

A production-quality marketing site for Nazora Creative Studios, a Kenyan creative
technology and digital solutions company. Five pages (Home, Services, About, Projects,
Contact), a floating WhatsApp button, and a floating AI assistant.

**Stack:** React 19 · TypeScript · Vite · Tailwind CSS v4 · React Router · Lucide icons.

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # typecheck + production build into dist/
npm run preview    # serve the production build
```

## Structure

```
src/
  components/   SiteHeader, SiteFooter, ContactForm, Chatbot, WhatsAppButton,
                PricingCard, FaqAccordion, Portfolio (+filters/grid), ProjectCard, Seo, ui
  sections/     Homepage sections 01–10 + Hero (one component per section)
  pages/        Home, Services, About, Projects, Contact, NotFound
  data/         site, services, packages, projects, faqs, home — edit copy here
server/
  chatHandler.mjs   Framework-agnostic AI chat handler (validation, rate limiting, LLM call)
  chatPlugin.mjs    Mounts the handler on the Vite dev server at POST /api/chat
public/         robots.txt, sitemap.xml, real project screenshots
```

Content is data-driven: prices, packages, services, projects and FAQs live in `src/data/`,
so updates never require touching layout markup.

## Environment variables

Copy `.env.example` to `.env`. **No variable is required to run the site** — every
integration degrades honestly instead of faking a success.

| Variable | Side | Required | Purpose |
|---|---|---|---|
| `OPENAI_API_KEY` | server only | no | Enables the live AI assistant. Read inside `server/` and never sent to the browser. |
| `AI_BASE_URL` | server only | no | Model endpoint. Default `https://freebuff.com/api/v1/paid`. |
| `AI_MODEL` | server only | no | Model name. Default `gpt-4o-mini`. |
| `VITE_ENQUIRY_ENDPOINT` | build-time | no | Server-side URL that receives contact-form JSON. |

### AI assistant — what happens without a key

The assistant is a **real** LLM-backed chat: `src/components/Chatbot.tsx` POSTs the
conversation to `/api/chat`, and `server/chatHandler.mjs` validates input, applies
per-client rate limiting, adds a system prompt grounded in the approved business
information, and calls the model.

When `OPENAI_API_KEY` is absent, the endpoint returns `503 not_configured` and the
chatbot says so, offering WhatsApp and the enquiry form instead. It never pretends to
answer.

To enable it:

1. Set `OPENAI_API_KEY` (and optionally `AI_BASE_URL`, `AI_MODEL`).
2. In development the Vite plugin serves `/api/chat` automatically.
3. In production, run the same handler behind a server/edge endpoint at `/api/chat`.
   It is a plain `(rawBody, clientKey) => { status, body }` function, so it drops into a
   Cloudflare Worker, Node server, or edge function. The Worker in `worker/` already wires
   it up for the Cloudflare/Sites deployment.

## Contact form — what happens without a provider

The form validates fully (required name, email format, at least one service, project
description; accessible inline errors tied to each field). Submission then depends on
configuration:

- **`VITE_ENQUIRY_ENDPOINT` set** — the form POSTs the enquiry. Success shows a
  confirmation; failure shows an error and prepares the WhatsApp handoff.
- **Not set (current state)** — the form does **not** claim a submission. It shows that
  online delivery is not yet configured, renders the fully formatted enquiry in an
  editable box, and gives working "Send on WhatsApp" and "Send by email" actions.

To go live, point `VITE_ENQUIRY_ENDPOINT` at a server-side endpoint with access controls
(for example a Supabase Edge Function writing to a table with insert-only RLS, so
enquiries are never publicly readable). Never put a service-role key in client code.

## Deployment

### Current deployment (Freebuff Sites / Cloudflare)

| Production (published) | https://site-c09746be39d84def8f6037bb362212c9.freebuff.page |
| Preview (published) | https://site-9eff040f382947fe8e58ed024389e9a4.freebuff.page |

The built Worker + assets live in `deploy/` (`manifest.json`, `worker.js`, `public/`).
`worker.js` is generated by concatenating `server/chatHandler.mjs` with `worker/worker.js`,
so the deployed chat endpoint and the dev endpoint share one implementation. Rebuild both
after changing either file:

```bash
npm run build
mkdir -p deploy/public && cp -r dist/* deploy/public/
{ cat server/chatHandler.mjs; sed '/^import { createChatHandler } from/d' worker/worker.js; } > deploy/worker.js
```

Then publish from the hosting panel (or the deploy tooling). After the **first** deploy, set
the `OPENAI_API_KEY` secret on the site to enable the live assistant.

The share image (`public/og-image.png`) and `og:image` tags point at the current deployment
origin so social previews never 404. **When a real domain is connected**, update:
`ORIGIN` and `SHARE_ORIGIN` in `src/components/Seo.tsx`, the canonical/OG tags in
`index.html`, `public/robots.txt`, and `public/sitemap.xml`.

### Other hosts

The site is a static SPA plus one optional serverless function (`/api/chat`).

- **Static hosting (Netlify, Vercel, Cloudflare Pages, etc.).** Upload `dist/`. Configure
  an SPA rewrite so `/*` serves `index.html` (a 404 fallback) — deep links and refreshes
  depend on it. `robots.txt` and `sitemap.xml` are emitted into `dist/` automatically.
- **Cloudflare Worker/Sites.** `worker/` contains a Worker that
  serves the assets, applies SPA fallback for client-side routes, and handles
  `POST /api/chat` with the same handler used in dev. After the first deploy, set the
  `OPENAI_API_KEY` secret in the hosting panel to turn on the assistant.

Update the canonical URL, Open Graph URL, `robots.txt` and `sitemap.xml` once the final
domain is confirmed — they currently point at `https://nazoracreativestudios.com`.

## Accessibility & performance notes

- Semantic landmarks, one `h1` per page, skip-to-content link, labelled form fields with
  inline `aria-describedby` errors, keyboard-operable accordion/filters/dialog with focus
  handling, and visible focus rings.
- `prefers-reduced-motion` disables entrance animations and ambient motion.
- Below-the-fold imagery is lazy-loaded with reserved dimensions; JS is code-split by route
  only where it pays off, and blur effects were deliberately kept small for low-end devices.

## Portfolio screenshots

Project thumbnails in `public/thumbnails/` are **genuine screenshots** of the live client
sites where they could be captured reliably. Where a reliable capture was not available,
the card renders a clearly designed placeholder panel with the project name and live URL
rather than fabricated client artwork. Refresh them with:

```bash
npm i -D playwright && npx playwright install chromium
node scripts/capture-thumbnails.mjs
```

## Content integrity

No invented testimonials, statistics, awards, staff, addresses or client logos. Hosting
and domain arrangements beyond the published Bronze inclusions, and any page counts or
timelines, are stated as items to be confirmed in the final quotation.
